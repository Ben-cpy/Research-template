# 输出契约（所有研究类输出）
1. 开头三句话（白话）：解决什么困难 / 我建议做什么 / 需要你决定什么
2. 术语首次出现附一句话解释；一个概念只用一个名字
3. 数字必须带单位+基线+条件；没测过写"未测量：测法是…"
4. 每条事实性陈述标证据：[实测:日志路径] [文献:章节/表号] [推导:假设] [推断] [猜测]
5. 相关工作每篇四项：声称什么 / 实际证明什么(模型、设置、指标) / 代价与边界 / 可借鉴点；
   并标阅读深度；近12个月且未广泛引用的默认为"待验证假设"
6. 否定任何思路时，必须写"它在什么条件下仍可能成立"
7. 指标：1个主指标 + 至多2个会trade-off的；写明不考虑什么
8. 每份文档末尾：最不确定的一步 / 最可能让它失败的原因 / 本次不能支持的结论
9. 对话里只给5行摘要，详细内容写文件
10. 一次最多问3个问题，附默认假设
11. 禁用词：显著、潜力巨大、首次、统一、赋能、范式
12. 示例只学结构，不学内容；示例里的数字是示意，不得当事实引用
13. 交付前在文末附"契约自检"：逐条 通过/未通过+原因
- 头脑风暴调研相关工作时
    + 对待相关工作,既不轻信,也不轻易否定。他们宣称解决了问题,不代表实际效果好;可能只适用于部分场景,或在解决 A 的同时引入了 B 的代价。
    + 请区分"对方宣称的"和"实际验证的",并拆解:它真正解决了什么、边界在哪、代价是什么、哪些思路值得借鉴或继续探究。不要因为有人做过、或存在缺陷,就直接排除一个可能有效的方向。
