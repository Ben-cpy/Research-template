# 交付约定

- 先给当前判断及其影响，再给关键依据与需要用户决定的事项；对话保持简洁，按问题需要展开，
  不固定行数，不强制附逐条“契约自检”。进度先按 [workflow](../docs/workflow.md) 自行核验，再据实回答。
- 省略免责声明、泛泛的风险提示和反复的“需谨慎/需验证”。只有当某个风险会实质性推翻结论或决定实验成败时，
  才用一句话点明，并说明它影响哪个判断或实验选择。
- 不确定时给出当前最佳推测、置信度及关键依据，不回避判断；推测仍须与实测结果区分，置信度不冒充测量值。
- 阶段交付呈现：值得关注的问题及原因证据；方法针对什么问题、最小对照、收益与代价；
  适用边界、负结果、未知项；建议继续/停止/补证的理由，以及需要用户作出的选择。
- 不用运行次数、耗时或脚本数量代替进展；允许本阶段没有值得推荐的方法，说明证据与原因。
- 关键结论链接可核查的文献或本地证据。分清作者声称、实际阅读/复现范围、实测、推导、
  推断与假设；不要求每句都贴标签。没有原始证据就说明未独立核验。
- 数字带单位、分母、条件与比较对象；未测写未知，可说明测法，不用估计填充结果。
- 运行完成、证据判断、用户审阅分别说明；Agent 自检不能代替用户认可或独立复现。
- 对前作和被否定思路说明有效条件与边界；方法效果同时报告代价，不自行宣称新颖或普遍有效。
- 各级 AGENTS.md 与 README.md 是稳定说明，日常工作不更新，也不呈现当前进度。
  具体问题的设计、证据、判断与反馈由所属 research.md 持有；顶层 `task-doing.md`、`task-done.md`
  仅维护任务与简短结果，不另建重复进度表、日报或候选卡。
- 用户可直接审阅相关探究目录，或随时要求根据实际证据汇报；不按十分钟周期询问是否继续。
- 用白话解释关键机制，术语首次出现时按读者需要解释；仅询问会改变方向或执行的问题，
  其余未指定项保留未知，不把默认假设写成用户事实。
