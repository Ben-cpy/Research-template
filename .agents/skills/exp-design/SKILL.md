# 量化实验设计

把具体 idea 变成能够推翻假设、支持下一步决策的验证方案。遵守项目 `AGENTS.md` 的配置与复现约束。

## 回答约束

- 先说验证什么、建议先做什么，再给设计；按请求控制篇幅，不固定对话行数或附逐条自检。
- 区分实测、文献、推导与待验证假设；关键主张附可核查来源，数字写清单位、条件和比较对象。未运行的预测不能写成结果。
- 从已有讨论、项目配置和输入中补齐信息。无法确定的关键项写 `TBD`、候选与决策影响，只询问会改变方案的问题；存在关键缺项时标为“设计草案，尚不可执行”。
- 先设计最可能推翻假设的最小实验。能靠推导回答时先推导，不强行安排实验；没有具体问题时先明确问题，不填空泛实验表。
- 设计请求本身不启动长实验；用户已授权设计并执行时，完成方案后继续授权范围内的执行。

## 方案必须说明

| 项目 | 回答要求 |
| --- | --- |
| 假设与目的 | 要验证的主张、事前预测、替代解释，以及什么结果会推翻假设 |
| 模型 / 系统 | 名称、版本或检查点、关键运行设置、选择理由；先选足以验证机制的规模。非模型任务填写被测系统 |
| 输入 / 测评数据 | 来源、版本、划分、样本量与预处理；区分调参或校准数据和最终测试数据，说明数据能验证什么 |
| 量化指标 | 默认一个主指标、至多两个关键权衡指标；写定义、单位、优劣方向、聚合方法和测量条件 |
| 基线与对照 | 与谁比较、改变什么、固定什么；控制硬件、预算与质量等可能混淆结论的条件 |
| 最小实验与判定 | smoke 检查实际输出，再验证假设；运行前确定支持、不支持、证据不足时的处理，以及停止或扩展条件 |
| 执行与记录 | 资源预算、外部配置入口、产物位置；长实验说明检查点与续跑方式，复现信息遵守项目规则 |

选择模型和数据时优先满足任务适配与可复现，再考虑权威性。优先考虑官方发布、划分明确、评测协议可核查的公开基准；具体推荐核查原始论文或官方来源，给出选择理由，不把知名度当作适配证据。
合成数据可以隔离机制，但不能代替真实任务效果证据；需要自建数据时说明必要性与局限。不适用字段写原因。

时延须明确单步或端到端、计时包含哪些成本、硬件与并发、预热与重复、聚合方式；准确率须明确任务、测试划分和评分规则。优化效率时明确质量通过条件及允许损失。
判定阈值说明依据；根据重复测量的波动报告不确定性。证据不足时不宣称成功或失败，否定某方案时说明仍可能成立的条件。

讨论时直接给出方案。正式实验沿用固定编号，详细方案由 `experiments/NNN_name/design.md` 持有，运行前在 `paper/exp_design.md` 登记简短设计，结果写 `TBD`；`paper/plan.md` 只引用编号。
运行前冻结预测与比较协议，后续修订保留旧版本，并遵守项目新建结果目录规则。不要仅因使用本 skill 就创建或运行实验。

## One-shot：集合查询

示例只教结构；以下配置与阈值均为教学示意，尚未执行，不作为项目默认参数或实测证据。

**输入：** 重复查询列表元素，想先转成集合。请设计最小实验，判断查询收益能否覆盖构建成本。

**输出：**

> 先固定列表规模，只改变查询次数，比较包含构建成本的总耗时。以下是未运行的设计草案。
>
> **假设：** 1000 次查询时，集合方案总耗时低于列表方案；若漏计构建成本，可能得到虚假的优势。
> **对象：** CPU 上的 Python 列表与集合；模型项不适用。Python 版本和实际硬件待固定并记录，当前尚不可执行。
> **数据：** 外部配置生成 1000 个互异整数；查询次数为 1、100、1000，命中率 50%，种子 7。两方案使用同一批保存的输入。合成数据用于隔离成本，不能证明真实业务普遍加速。
> **指标：** 主指标为每批查询端到端耗时（ms，越低越好），包括集合构建；答案必须全部一致，不允许正确性损失。
> **对照：** 列表查找为基线；固定输入、硬件和版本。预热 2 次，配对测量 5 次，交替执行顺序，报告中位数和全部重复值。
> **判定：** 答案一致，且 1000 次查询下全部配对测量都更快，暂时支持假设；全部更慢则不支持该条件下采用；快慢混合则证据不足。此规则只用于初筛，不作为统计显著性的证明；临界或高波动结果需另定重复测量方案。
> **执行与保存：** 先用 10 个元素、10 次查询检查答案和计时边界，通过后再运行计划设置。仅需本地 CPU 短运行，实际耗时待记录；参数写入新实验的配置文件，保存方案、输入、原始计时及复现信息，运行前登记实验编号。
> **下一步与边界：** 先补齐环境和配置入口。支持假设后再测试真实输入分布；若不支持，更多查询或复用集合时仍可能成立。
