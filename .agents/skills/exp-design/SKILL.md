# 量化实验设计

把明确问题变成能区分解释、支持下一步决策的方案；不要求先有解决方法。
共同的授权、记录与复现规则遵守项目 `AGENTS.md`、`docs/workflow.md`，
目标与硬门槛以 `context/profile.md` 为准。

## 设计要点

- 明确主张、竞争解释、事前预测，以及哪些观察支持、反驳或无法区分它们；优先最小检查，能推导时先推导。
- 指定系统版本与设置、输入来源和划分、样本选择与数量理由；区分开发数据与未参与设计的验证数据。
  选择足以检验机制的规模，模型与数据推荐核查原始来源；合成数据的结论限于其覆盖条件。
- 选择强简单基线，说明改变什么、固定什么，控制数据、环境、预算与质量差异。
  指标写明定义、单位、分母、聚合方式及测量范围，同时覆盖收益、必要条件和代价。
- 明确实验单位（任务、用户、运行等）和独立性；同一任务的多步或多次重试不能充作多个独立任务。
  可配对时用相同输入比较，报告配对差异；随机系统区分任务间差异与同一任务重复的波动。
- 按预期差异、波动与预算决定重复数和适当的不确定性表达；样本不足时保留探索性结论，
  不以少数全胜或未达显著性直接证明有效或无效；多设置筛选或看结果后临时扩样的分析标为探索性。
- 时延明确端到端边界、构建等成本、硬件并发、预热与执行顺序；任务成功明确评分规则和失败处理。
- 运行前冻结比较协议、阈值依据、停止与扩展条件；先 smoke 并查看实际输出。
  写清资源预算、配置入口与证据位置；长运行说明检查点。协议变更保留旧版并按 workflow 新建运行。

## 交付

先说明验证什么、建议先做什么，再展开与决策有关的设计；窄问题无需完整表格。
关键缺项标为“设计草案，尚不可执行”，说明候选及影响；不补造用户门槛。
只请求设计时交付方案，已授权执行则继续范围内验证，不因加载 skill 自动启动实验。

## 简例（教学方案，未运行）

列表转集合是否划算：固定同一输入，只改变查询次数，比较包含构建成本的每批耗时并核对答案。
预热后交替顺序做配对测量，保存每对差值；若差异与波动相近，先报告证据不足。
这只能筛查该输入条件，不能由单个输入上的多次计时推断真实任务普遍加速。
