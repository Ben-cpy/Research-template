# 自主探究工作流程

项目目标与资源边界只在 [profile](../context/profile.md) 维护，研究偏好与交付要求见 context。
各级 AGENTS.md 和 README.md 是稳定说明，日常探究不改写；它们不记录当前进度。
用户明确要求修订相关规范时才修改。本页定义可复用的执行机制。

## 启动与自行判断进度

1. 理解用户宏观目标，区分硬约束、偏好与未指定项。只追问会影响方向、权限或可执行性的歧义，
   其余未知及影响留在相关研究记录，先推进不依赖它们的工作。
2. 先阅读顶层 `task-doing.md`、`task-done.md`，再自行查看已有业务代码、配置、
   `AI-discover/` 编号目录、正式实验和相关 Git 变更。
   从具体问题的 `research.md` 查找设计、证据链接与用户意见，再核验实际输入、日志、
   检查点、结果和退出码。存在运行中任务时，必要时检查实际进程或设备，避免重复启动。
3. 区分已实现、实际运行过、证据支持、用户已审阅和仍未知；不能只凭文件存在、修改时间、
   旧记录中的“已完成”或历史下一步推定状态。记录与产物不一致时，以可核验的证据修正判断；
   缺失证据明确保留未知，不要求用户先整理进度，也不为补状态盲目重跑已有实验。
4. 用户要求开始/继续即授权该范围内的正常研究动作。未细分阶段时，以宏观目标为本轮探索范围，
   不要求用户再拆任务。按需在相关研究记录保留带日期的指示来源与适用范围；
   任务统一在两个顶层任务文件流转，不另建重复进度表。
   整理模板或讨论方案本身不等于启动研究授权。
5. 依据上述核验选择最值得回答的未知，说明新检查将改变什么判断，随后自主推进。
   选数据、对照、必要依赖、最小实现和范围内的转向无需逐项确认；说明用途并冻结版本。

接续工作的依据是实际证据；两个顶层任务文件提供任务入口和简短结果，不能替代证据核验。
不创建或维护 `status.md` 等全局状态文档，也不在顶层 `AGENTS.md`、`README.md` 保存
任何当前项目状态。Agent 只能通过实际探查项目了解进展，不能直接采信文档中的状态自述。
本模板保存工作约定和证据；执行会话结束后，新会话重新核验并接续，不假定文件会自动启动后台任务。

## 任务清单与流转

- 新想到的 idea 和核验后确认尚未完成的事项，先去重写入顶层 `task-doing.md`，再执行。
  教学示例、占位提示和已失效的历史建议不自动变成待办；无任务且无保留示例时保持空文件。
  用户要求保留的格式示例在第一行标明“示例”，只作排版参照，不执行、不迁移，也不作为真实结果或证据。
- Agent 在当前目标、约束与授权范围内，结合价值、依赖和实际条件持续从清单选择任务。
  正在执行的任务仍留在 doing 中；登记任务不代表扩大授权，也不自动启动研究或后台运行。
- 任务执行结束后，无论结果积极或负面，保留原有两行并移至 `task-done.md` 末尾，
  补充第三行结果，同时从 doing 删除。暂时阻塞或尚未执行完的任务留在 doing，
  在第二行简述阻塞条件；若已决定终止尝试，则移至 done 并如实说明原因及证据缺口。
- 两个文件只放任务条目及用户要求保留的示例，不加独立说明、表格或复选框；不同任务之间均空两行。
  doing 每项恰好两行：第一行用非常通俗的话简述任务，可用 Markdown 标题；第二行具体描述要做什么，不超过 100 字。
  done 每项恰好三行：前两行沿用原条目，第三行以 `积极：` 或 `负面：` 开头，
  用不超过 100 字的通俗表述说明大致结果。未验证或受阻终止须直说，不能写成假设已被推翻。
- 任务文件只保存简短描述和结果；具体设计、证据、判断与反馈仍在所属研究记录中维护，
  可在条目中用短链接指向它们。完成一项后将新产生的后续事项登记到 doing，再继续选取任务。

## 两类探究与选择标准

| 类型 | 回答什么 | 应留下什么 |
| --- | --- | --- |
| 发现问题与追查原因 | 什么问题在目标场景真实存在、值得解决，在哪些条件发生，可能为何发生？ | 现象、影响、可复核证据、竞争解释与未排除因素 |
| 思路或方法的最小有效性验证 | 针对明确问题，某个干预是否起作用，是否值得继续？ | 最小实现、必要对照、收益与代价、适用条件和失败/未知 |

二者相互推进，不要求先证明全部根因才能尝试干预，也不把相关性当成根因。
问题与方法可以多对多；阅读、推导、复现、环境修复和数据处理服务于明确未知，
不另开无目标工程线。没有运行的阅读判断不能写成实测。

优先用阅读、现有证据或最可能推翻假设的最小实验筛选，做结果不同就会改变决策的检查。
主动检查有实质差异的假设与竞争解释，避免只给偏好方法找佐证；不固定问题数、
方法数或平均分配资源。收敛写明依据，负结果、不确定及推导结果都可以有价值。

相关工作分清作者宣称、实际验证与本项目推断，核查原始论文/官方资料和实际阅读范围。
判断有效条件、对照、代价与可借鉴机制，不能因有人做过或存在缺陷就排除方向。
向新场景移植时分清原方法语义、适配实现与目标条件的变化；迁移失败不直接反证原工作，
跑通部署也不自动成为贡献。

## 约 10 分钟的执行尺度与继续条件

- 单次任务执行优先采用约 **10 分钟**能得到有效信号的规模，用于控制试错成本。
  这是大致参考，不是严格墙钟上限，不是汇报周期，不要求按十分钟切断阅读、分析或完整研究问题。
- 接近或超过参考时长时，Agent 自行判断继续、检查输出、缩小输入、排查异常或换一种检查。
  正常有进展可适度延长，不要求每次事前写延期申请。
- 一个任务结束后，依据证据自主安排下一项，不停下来问“是否继续”。
  有价值结果可随时汇报，汇报不自动中断当前目标下已授权的后续工作。
- 持续较久仍没有新增证据时，检查原因并调整方案，避免无目的等待或重复尝试。
  有必要的长实验先判断资源、检查点和停止条件；已有授权覆盖则直接执行。
  仅在明显超出已授权时间/费用/设备占用，或新增外部权限时请求用户决定；
  不把“超过十分钟”本身当作重新授权理由。
- 用户明确给定的总预算、资源上限与检查点仍有效；它们与上述参考尺度分别处理。
  未给总预算时，在当前执行会话和已授权资源内持续推进，不默认无限费用或跨会话后台运行。
- 需要改变硬约束或宏观目标、触及明确总预算/暂停指令、到达用户指定的审阅关口，
  或所有合理的范围内路径都被关键缺失信息/权限阻塞时，才等待用户。
  局部受阻可继续其他授权工作，不将内部选题和正常方法取舍交回用户逐项审批。
- 同一稀缺设备默认单负载，避免污染测量。模板不绑定特定模型或子 agent。

## 探究记录与证据

新问题使用 `AI-discover/<递增编号_主题>/`，已有编号不重排。
参照 [研究记录模板](../AI-discover/000_example/research.md) 创建 `research.md`；
000 是教学例子，不是已开展研究。不要求为每个小运行新建探究，也不强制创建 README。

- `research.md` 保存问题、假设与竞争解释、最小检查、输入和对照、指标与判定条件、
  配置/命令及证据链接。根据实际任务取舍字段，不适用项说明原因。
  方法验证链接所针对的问题，说明预期机制；记录服务于判断，不为填表增加工作。
- 每项计算前冻结设计与比较口径，先做 smoke 并查看实际输出。允许收益与代价交换；
  硬质量门槛以 profile 为准，不要求所有指标同时提升，也不发明统一胜出阈值。
- 新运行使用新的 `runs/<run-id>/`；兼容续跑沿用原运行。计算前保存完整配置、精确 commit、
  diff、执行相关未跟踪/被忽略源码副本与哈希、输入身份及版本、依赖和软硬件环境。
  外部依赖固定版本并保留可恢复来源；无法恢复时明确证据缺口。
- 运行结束补充命令、起止时间、退出码、原始日志、指标和异常。采用已有 JSON/YAML 或
  provenance 格式即可，不重复造日志。阅读/分析只需来源与推理，不强造运行文件。
- 失败、部分运行、fallback 和未测均保留。未知指标写 null/未知，不写 0。
  数字带对象、单位、分母、基线、输入/输出条件及测量范围；代理指标、估计、历史结果、
  当前测量和端到端效果分开，不混合条件不同的结果。
- 新配置/代码/输入/环境使用新运行目录；只有身份和状态兼容才续跑。
  历史原始证据不回写，新分析与用户反馈追加到研究记录并链接原运行。
- 研究记录、脚本、配置和紧凑结论进 Git；runs/results/figures 默认忽略，需单独备份。
  备份位置在所属研究记录注明；未备份标明缺口，不把代码已提交当作原始证据已备份。

工作结束前保留新增观察、证据链接、反证与未解决问题，并同步任务的登记与完成迁移，
以便下次核验和减少重复工作。
不更新 AGENTS.md/README.md，不要求把每次操作总结成全局进度，也不能把自述记录当成验证证据。

## 用户审阅与反馈

用户可随时询问进展，Agent 从实际文件与证据直接回答，不要求用户阅读过程日志。
优先交付值得审阅的问题、方法、收益与代价、负结果、未知及重要取舍，
链接到所属 `research.md` 和关键证据。可以没有值得推荐的方法，不用次数或时长代表进展。

用户查看相关目录后给出意见；有必要持久保留时，在所属研究记录中按日期注明来源与适用范围。
全局意见在一个相关记录中保存，其余位置引用，不新建重复进度表或改写历史判定标准。
普通反馈据此调整后续检查；用户明确要求改变稳定目标或规范时才修订对应 context。
同一宏观目标和约束内可继续自主探索；下一阶段宏观目标由用户给出，不把未回复当认可。

## 转入正式实验与论文

探索阶段不必填写论文文件。只有用户选定或已授权论文计划明确包含的验证才进入 experiments；
一次通过不自动晋升。该目录的 001_example 是教学例外。
正式实验保留探究来源和冻结证据链接，不整体复制流水账或搬走原始证据。

`paper/exp_design.md` 统一维护正式设计、协议与简短结果；配置、脚本和运行产物持有执行细节。
实验 README 只提供稳定的用途、入口与使用说明，不追加进度和结果。
`paper/plan.md` 组织论点与章节并引用实验编号，不复制结果数值。
可复用实现整理入 src 或已有业务目录后，正式实验不依赖探究代码。
